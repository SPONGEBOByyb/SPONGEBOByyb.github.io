Hexo博客故障排查与站点配置

发表于2026-10-15|更新于2026-10-16|工具与环境
|阅读量:

记录一次博客"突然跑不起来"的排查过程，以及顺手把站点配置里遗留的问题一起修掉。

问题一：hexo 命令全部报错

现象

全局的 hexo-cli 还在，但它找不到博客目录下的本地 hexo 包。

排查

  • node_modules/hexo 文件夹存在，但里面只有空的 bin/ 和 dist/，连 package.json 都没有
  • 统计整个 node_modules：740 个文件夹，只有 22 个文件 —— 目录骨架还在，文件全没了
  • 文件夹修改时间都是同一时刻，而上一次成功生成站点的时间更早，说明是中间某次操作把它清空了（中断的 npm install、清理软件、同步盘等都可能）

解决

package.json 和 package-lock.json 都完好，直接按锁文件重装即可：

npm ci 和 npm install 的区别：ci 会先删掉 node_modules，再严格按锁文件装，不会改动 package.json / package-lock.json，适合"恢复环境"。

问题二：重装后头像、背景图、网站图标都没了

原因

_config.butterfly.yml 里引用的是 /img/new.jpg（头像、favicon）和 /img/CS_Top.jpg（顶部图），而这些图片之前被我直接放进了 node_modules/hexo-theme-butterfly/source/img/。

主题是通过 npm 安装的，node_modules 一重装，主题目录被还原成官方默认文件，自定义图片自然就丢了。

解决

  1. 从上次部署留下的 .deploy_git/img/ 里找回原图（hexo d 会在本地保留一份已部署的完整站点）
  2. 放到博客根目录的 source/img/ 下：

Hexo 会把 source/ 下的文件原样复制到站点根目录，所以配置里的 /img/new.jpg 不用改。以后无论怎么重装依赖、升级主题，图片都不受影响。

原则：不要修改 node_modules 里的任何东西。 自定义图片放 source/img/，自定义样式用 _config.butterfly.yml 的 inject 引入 source/css/ 下的文件。

问题三：源码只有本地一份

GitHub 上的 xxx.github.io 仓库存的只是 hexo d 生成的网页，Markdown 原稿、图片、配置都只在本地。这次如果丢的不是 node_modules 而是 source/，就真的找不回来了。

解决：新建一个私有仓库存源码

  1. GitHub 新建仓库 blog-source，选 Private，不要勾选 README / .gitignore / license

Hexo 初始化时自带的 .gitignore 已经排除了 node_modules/、public/、.deploy*/、db.json，直接用就行。

问题四：站点配置里的默认值没改

都在根目录 _config.yml 里。

url 还是 example.com

Butterfly 文章底部的"本文链接"、分享链接，以及 sitemap / RSS 都靠这个字段生成，不改的话全部指向 example.com。末尾不要加 /。

时区为空

留空时使用运行 hexo 那台机器的系统时区，换到 CI 或时区不同的机器上，文章日期可能差 8 小时。

描述和关键词为空

description 会写进页面的 <meta name="description">，影响搜索引擎展示的简介。keywords 在 Butterfly 4.x 里不会输出成 meta 标签（搜索引擎也基本不看它了），填上只是留个记录。

问题五：多余和过旧的依赖

hexo 7 → 8、butterfly 4 → 5 都是大版本，Butterfly 5 改了不少配置项，需要对照新模板迁移 _config.butterfly.yml。现在能用就先不动，真要升级先确认源码已备份，再在单独分支上试。

顺手整理：文章分类

之前所有文章只有几个很粗的标签、没有分类，这次统一补上了：

  • 分类按技术领域：前端开发 / AI与深度学习 / 推荐系统 / 算法刷题 / 工具与环境
  • 标签分两类：内容性质（学习笔记、面经、八股、项目实战）+ 具体技术（Vue、PyTorch、Transformer……）

注意字段名是 tags，写成 tag 不会报错但也不会生效。

另外 permalink 用了 :title，如果把文章挪进子文件夹，:title 会带上文件夹路径，文章链接会变、图片相对路径也会断，所以分类只改 front-matter，不移动文件。
