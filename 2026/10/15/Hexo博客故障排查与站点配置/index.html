Hexo博客整理与优化全记录

发表于2026-10-15|更新于2026-10-16|工具与环境
|阅读量:

这篇记录了一次对博客的"大扫除"：从 hexo 突然跑不起来开始，一路排查环境、备份源码、修站点配置、整理全部笔记、更换 Markdown 渲染器、重做全站样式，最后补齐框架上缺的功能。每个问题都写了现象 → 原因 → 解决办法，最后一节是还没处理的问题和打算怎么做。

博客环境：Hexo 7.3 + Butterfly 4.13，部署在 GitHub Pages。

一、环境故障

1. hexo 命令全部报错

现象：

原因：node_modules 被"掏空"了——740 个文件夹只剩 22 个文件，node_modules/hexo 里只有空的 bin/ 和 dist/，连 package.json 都没有。文件夹的修改时间晚于最后一次成功生成的时间，应该是某次中断的 npm 操作、清理软件或同步盘把文件删了。

解决：package.json 和 package-lock.json 完好，按锁文件重装：

2. 重装后头像、背景图、网站图标都没了

原因：自定义图片当初被放进了 node_modules/hexo-theme-butterfly/source/img/。主题是 npm 装的，node_modules 一重装就被还原成官方默认文件。

解决：从上次部署留下的 .deploy_git/img/ 找回原图，放到博客根目录的 source/img/。Hexo 会把 source/ 下的文件原样复制到站点根目录，配置里的 /img/xxx.jpg 不用改。

原则：永远不要改 node_modules 里的东西。 自定义图片放 source/img/，自定义样式和脚本放 source/css/、source/js/，再用 _config.butterfly.yml 的 inject 引入。

3. 源码只有本地一份

GitHub 上的 xxx.github.io 仓库存的只是 hexo d 生成的网页，Markdown 原稿、图片、配置都只在本地。

解决：新建一个私有仓库 blog-source 专门存源码（不要放进公开的 github.io 仓库）。Hexo 自带的 .gitignore 已经排除了 node_modules/、public/、.deploy*/、db.json。

GitHub 仓库页面可能提示 “Your main branch isn’t protected”。分支保护在免费账号的私有仓库上用不了，单人备份仓库也不需要，点 Dismiss 即可。

三、文章整理

4. 分类与标签

问题：所有文章都没有 categories，只有 Study / Algorithm / Web 这几个很粗的标签，而且划分不一致；有一篇写成了 tag:（少个 s，Hexo 不认，等于没标签）；还留着 Hexo 默认的 hello-world.md。

方案：分类按技术领域，“面经”"八股"这类性质用标签表达。

分类 内容
前端开发 HTML+CSS、JS、Vue、若依
AI与深度学习 机器学习、PyTorch、Transformer、多模态、大模型微调、Agent 面经
推荐系统 推荐系统笔记与八股、FTRL、天池代码解读、搜广推面经
算法刷题 hot100、ACM 输入
工具与环境 Git、Missing Semester、Hexo

标签 = 内容性质（学习笔记 / 面经 / 八股 / 项目实战）+ 具体技术（PyTorch、Transformer、Vue……）。

permalink 用了 :title，把文章挪进子文件夹会让 :title 带上路径、文章链接改变，所以分类只改 front-matter，不移动文件。

5. 内容细节

  • 错别字：XBoost → XGBoost，演讲过程 → 演进过程
  • 8 篇笔记正文开头又写了一遍 # 标题，和文章标题重复，删掉
  • 17 个代码块没写语言（没有高亮），补上 python / bash / json / text
  • JS 笔记（4200 行）拆成 4 篇、HTML+CSS 笔记（1900 行）拆成 2 篇：
    • 第一篇沿用原文件名，原链接不失效
    • 图片跟着内容移到各自的资源文件夹
    • 每篇开头加系列导航（用 Hexo 的 post_link 标签互相链接）

小坑：hexo-asset-img 给每张图生成随机类名，偶尔以 www 开头时会被 Hexo 的 img 标签误判为网址，导致那张图显示不出来。重新 hexo g 一次就好。

四、更换 Markdown 渲染器

6. 公式显示错乱

现象：部分公式里的下标乱掉，变成斜体。

原因：原来的渲染器 hexo-renderer-kramed 早已停止维护，而且不认识公式：它先把公式里的两个 _ 当成斜体标记，等浏览器端 MathJax 再来渲染时公式已经坏了。

解决：换成 markdown-it，并在生成时直接把公式渲染成 SVG：

同时在 _config.butterfly.yml 里关掉浏览器端的 mathjax.enable，避免重复处理。

加粗紧挨中文标点时不生效，显示成 ** CommonMark 规范对中日韩标点的判定有缺陷 装 markdown-it-cjk-friendly；它是 ES 模块，不能直接写进 plugins，改用 scripts/markdown-it-cjk.js 通过渲染器的过滤器注册
侧边目录里显示出一大段 CSS mathjax3 在每个公式外面内联约 3KB 的样式，标题里有公式时被目录抓走 scripts/mathjax-style.js 在渲染后去掉内联样式，样式统一放到 source/css/mathjax.css 加载一次

五、样式

所有样式都在 source/css/custom.css，通过 _config.butterfly.yml 引入，不改主题文件：

9. 全站：参考 Apple 官网的设计语言

  • 颜色：浅灰背景 + 白色卡片，近黑文字，蓝色强调；所有颜色定义成 CSS 变量，深色模式另配一套
  • 卡片大圆角、柔和阴影、悬停微微上浮；按钮和标签胶囊形；导航栏滚动后毛玻璃
  • 正文标题靠字号、字重、留白区分层级；加粗用淡蓝"荧光笔"高亮；嵌套列表加缩进和细线
  • 引用块、表格、图片圆角化；无封面的"相关推荐/上下篇"改成浅灰卡片
  • 直接覆盖 Butterfly 自带的变量（如 --card-bg、--font-color）最省事；深色模式要用 :root[data-theme="dark"] 才能压过主题自己的定义

10. 代码块

问题 1：工具栏的复制、折叠图标显示成问号。
原因是我给 figure.highlight *（代码块里所有元素）设了等宽字体，把图标字体也覆盖了。改成只作用于 pre, code, .line。

问题 2：想要深色 Mac 窗口风格。

  • highlight_theme: mac：深色背景 + 红黄绿三个圆点
  • 工具栏右侧改成 [语言] [复制] [全屏] 小按钮，窄屏只显示图标
  • 主题没有全屏功能，用 source/js/code-tools.js 加了一个，Esc 退出
  • 行号用 CSS 隐藏，而不是在配置里关掉——因为主题的复制功能依赖行号的表格结构

小坑：主题复制成功后，会把"复制成功"写进工具栏最后一个元素的前一个元素。全屏按钮如果直接追加在末尾，提示就会写进复制按钮里并把它隐藏。所以全屏按钮要插在复制提示前面，显示顺序交给 CSS 的 order。

12. 没有站内搜索

索引约 470KB，只在点开搜索时才下载，不影响平时打开页面的速度。

13. 图片多的笔记打开很慢

现象：「推荐系统学习笔记」有 115 张图（约 12MB），「机器学习」约 8MB，一打开页面就全部下载。

解决：开启 Butterfly 自带的图片懒加载，图片滚动到附近才加载。

开启后图片的 src 会先换成一个 1×1 的占位图，真实地址放在 data-lazy-src 里，滚动到附近才替换。实测打开「推荐系统学习笔记」时 115 张图只加载了屏幕内的几张，其余随滚动加载。
